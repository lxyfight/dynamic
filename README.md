# dynamic · 动态需求下的卡车与无人机协同调度

固定回路卡车沿高速向双侧交接站补给药品、回收样品，驻站无人机服务客户。站内实时库存连接干线运输与末端飞行。系统联合决定动态取件接拒、无人机任务、卡车回收及停站动作，目标为全日期望净利润最大。

**2026-11-26 修订：全天固定等待间隔 h、逐车独立计时、完整联合候选、同一个后决策 VFA。** 正式问题描述、SMDP、约束、利润及候选特征见 **[model.md](model.md)**。本次提供实现与开发训练入口；候选特征尚待正式消融，h 尚未选出经独立测试确认的最优值。

## 快速运行

Python 3.11 或更高版本，在仓库根目录运行：

```shell
python -m pip install -r requirements.txt
python demo.py --orders 20 --share 0.4 --pattern uniform --temporal peak --h 5
```

未提供模型时运行 **Unified-Myopic**：使用新版联合候选，但未来价值权重为零。默认 h=5 是可运行配置，不是已验证的最优值。每次运行检查完整履约与独立账本。

提供新版训练模型后，在同一运营日比较 Unified-Myopic 与 Unified-VFA：

```shell
python demo.py --orders 20 --pattern dual --temporal flat --model tmp/unified_vfa_development/selected_model.json
```

默认使用模型保存的 h，显式 `--h` 必须与模型一致。旧 `results/frozen_six.json` 不能作为新版模型输入。`python demo.py --legacy` 保留旧六特征算法示例。

## 需求生成与固定 h

- 固定实验总量 N 和动态度 d，取件数为 `round(N*d)`，其余为期初配送。实际隐藏取件总量仅属于实验生成器，在线策略不可读取。
- 空间 `uniform` 为沿线区域均匀分布，`dual` 为两个截断高斯热点。空间对照共享相同释放时间和重量随机流，各自按实际 delivery 位置生成 I0。
- 时间 `peak` 在第 1–150、151–350、351–590 分钟的**每分钟强度比**为 1:3:2；`flat` 为等概率到达。固定总量后抽样时刻，不再声称当天总量服从无条件泊松分布。
- 空间和时间可以交叉配置。只改变时间形态会保留位置、重量和 I0。默认 peak 保留旧场景抽样兼容性。
- 在线预测来自独立的 160 个合成历史日，包括城市分时率与几何服务时滞摘要，不读取测试日未来请求或由当天真实 N、d 推出剩余取件。

全天各车使用相同 h，但按各自开始等待时刻设置 `t+h`。例如 h=10，9:03 开始等待的车在 9:13 复核，9:07 开始的车在 9:17 复核。没有全网共同复核时间格点。提前新订单或作业事件照常处理；继续原等待时保留原到期时刻，首次等待或到期续等才设置新计时器。已知货物的装货预约等待不强制为 h 的整数倍。

h 在离线验证中选择：各 h 按同预算训练，在相同验证实例上比较平均全日净利润，冻结后再独立测试。主实验先用跨场景共同选择的 h；按需求场景分别调参应单独报告。

## 事件驱动的联合决策

1. 仅用期初 delivery 形成共同初始分配与车机计划。相应货物在本站卸货完成并齐备后才可由无人机发运。
2. 订单到达、装卸完成、无人机卸机就绪、等待到期等异步事件更新状态；存在实际选择时调用策略，同一时刻合并事件后决策。
3. 构造接拒、未起飞航次插入/新航次、已有/新增车趟回收、各车离站/预约等待/主动等待/续等的完整候选。多个卡车可以同时等待。
4. 完整回放检查库存、逐段载重、续航、delivery 期限、执行锁定及客户—站—卡车—仓库完整回收链。所有保留的基础计划先扩展等待组合，再由同一个 `J_known + W_theta` 排名，不先固定一个接单计划后单独评价等待。
5. 执行至下一事件，全日结束后审计履约、收入、车机运营费用、拒单及 pickup 返仓迟到费用。

已排定但未起飞的航次允许可行插单，包括尊重已锁货物和进行中操作的装载阶段。实际起飞后当前模型锁定整个航次的访问序列及返站点。程序采用有限候选预算和邻域搜索，日志记录截断，不宣称穷举全部连续时间方案。

## 统一 VFA 与开发训练

当前实现六组、七维候选代理：近 h/更晚既有车机链机会、新增车趟覆盖增量、需求加权无人机拥挤、回收容量、未来取件迟到暴露、既有配送期限余量。特征只使用公开预测和已知计划回放。城市级最近站几何时滞仍是粗代理，不能理解为所有未来订单可同时服务的保证。精确定义见模型及代码。

训练标签为 `G - J_known`，两项使用相同全日账本，避免重复计入已知收益。开发入口采用各运营日等权、无截距的缩放岭回归，迭代仿真并探索候选。模型保存特征顺序、缩放、权重与固定 h。

```shell
cd code/e1_v04
python run_unified_vfa.py train --h-values 5 10 --train-layouts 710 711 --validation-layouts 810 811 --orders 20 --patterns uniform dual --temporal peak flat --iterations 2 --output ../../tmp/unified_vfa_development
```

输出协议、各 h 的训练/验证记录与 `selected_model.json`。训练和验证布局必须隔离，输出目录必须为空。上述配置用于开发，正式特征消融、多训练种子及独立测试仍须按实验安排完成，不能把小样本验证成绩当成论文最终结论。
