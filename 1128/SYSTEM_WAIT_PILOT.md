> 历史机制先导（2026-11-25）：本页描述旧自适应 h，不是当前默认策略。2026-11-26 的全天固定 h、逐车计时、统一 VFA 方案见 [model.md](model.md) 和 [README.md](README.md)。保留本页用于解释和复现旧结果。

本次提交保留旧先导的报告与汇总；下文目录表中的 `worlds/`、`cases/`、`status/`、`traces/` 是运行程序生成的本地原始文件，未上传。原协议保存了当时源码与输入哈希；使用修订代码重跑时应另建输出目录并记录新协议，不应覆盖旧结果。

本阶段保留已经冻结的六特征 VFA 接单与回收调度器，新增一个随日内需求变化的**全网统一复核间隔 h(t)**。同一时刻，所有站点和车辆使用相同的 h(t)；客户空间分布与日内到单强度共同决定它。当前车辆、无人机和货物状态用于判断某辆车能否等待、是否离站，不用于给不同站点计算不同的 h。

这轮是候选覆盖、单次等待反事实和连续复核状态的开发先导，**尚未训练新的等待策略，也不预设等待能提高利润**。截至2026年11月25日本次更新，273项回归测试全部通过，用时103.307秒，包含既有PI相关测试；32日先导和313条完整回放全部完成。源码、规则及场景按启动时的协议冻结，原先发布的高需求对照和等待负结果保留为历史版本。

本批单次系统间隔干预相对离站的平均收益差为−15.50元（10胜、2平、20负）；最多三次复核的探索轨迹平均收益差为+11.12元（17胜、15负）。这些是预定采样状态上的干预结果，不是完整已学策略的性能。详细分组、共同可行样本比较和账本机制见[先导结果与核验](results/system_wait_pilot_20261125/REPORT.md)。

## 1. 统一间隔怎样计算

设历史估计的城市 c 在整数释放时刻 u 的到单强度为 λ_c(u)，F_c 为该城市历史取件几何就绪时长 L 的经验分布函数。使用以下全网期望机会量：

\[
B(t,h)=\sum_c\sum_{u\in\mathbb Z:\,t<u\leq t+h}
\lambda_c(u)F_c\bigl(h-(u-t)\bigr).
\]

释放时刻的求和仅覆盖公开的请求揭示期。L 按每个历史客户到**最近的可服务交接站**计算，包括空闲无人机往返飞行、客户服务和返站卸机时间。它不包含实时排队、已占用无人机、当前卡车位置与余载，也不包含后续卡车装货。因此 B 是空间与时间共同决定的**几何机会代理**，不是“这些取件一定能赶上当前卡车”的证明；实际候选仍须经过完整物理回放。

需求预测来自独立生成的160个高需求历史运营日，历史总单数从75、100、125、150、175中抽取，动态度从0.2、0.4、0.5、0.6中抽取。历史时间流、位置流和重量流使用独立种子，不读取被评价当天的真实总单数、实际取件数量或未来订单。每城市的 L 分布压缩为128个等权中点分位数，写入公开字段 `demand_model.spatial_service_lags_by_city`。历史时间流在均匀／双簇之间配对，因此空间差异通过 F_c 进入规则，不依赖额外制造的到单强度差异。

规则取满足 B(t,h) ≥ 0.5 的最小整数 h，范围为2至30分钟；若没有达到阈值，则取30分钟。0.5是预设的期望机会量阈值，未根据利润调参。独立几何诊断发现，10分钟内的就绪机会量普遍达不到0.5，因此保留原阈值并将上限扩为30，而不是为获得正收益调整阈值。

以布局610的生产历史摘要为例，t=0、150、350时，均匀分布得到 h=24、16、18分钟，双簇分布得到22、14、16分钟。这仅说明规则能够响应空间和日内需求，不能据此推断策略收益。

**h 是最长复核间隔，不是必须等待的时长或强制离站时刻。** 若某辆车在时刻 t 选择等待，其预约复核按 t+h(t) 设置，在揭示期边界处可截短；输出分别记录请求的间隔与实际间隔。相关新请求或货物就绪事件仍可提前触发决定。不同车辆开始等待的时间可以不同；“全网统一”指同一时刻使用同一间隔函数，不要求所有车辆同时停靠或同时离站。揭示期结束后，不再为未知未来需求新增主动等待。

主规则与消融的接口为：

```python
from e1_sim.system_wait import SystemWaitRule

main_rule = SystemWaitRule(signal="ready", target_expected=.5, max_h=30)
temporal_only = SystemWaitRule(signal="arrivals", target_expected=.5, max_h=30)
h = main_rule.interval(known.public, known.now)
```

`arrivals` 只累加未来到单强度，作为去除空间就绪信息的消融。主先导同时保留2、5、10、20、30分钟的固定间隔。若主规则或消融的 h 与固定值重合，复用同一反事实分支并标记其角色。

## 2. 本次修复和比较边界

事件处理现在让卡车到站后的同刻完成事件、请求披露先完成，再决定是否继续行驶。即使本站没有预先预约的装卸，也应保留合法的离站／等待决策机会。给一架无人机插单或令一辆车等待时，延误沿设备、货物和运输依赖传播；无依赖的其他设备不因时间位置相近而整体后移。

基线使用冻结的六特征模型，**不主动等待尚未知的未来需求，但允许为已披露、已预约的货物等待装车**。两者在候选生成与记录中分开处理。每次停站记录已主动等待分钟数、复核次数和停站身份，用于发现连续续等问题；已有装卸作业、道路行驶及已起飞航次仍遵守执行承诺。

每个运营日只生成一次订单流和初始配送方案 I0，并记录其哈希。基线运行过程中，按预先规定的规则选取一个公共状态：在预设的0、200或400分钟目标之后，选择第一个可比较等待机会；若其后没有机会，则使用当天第一个机会。目标只由实例种子决定，不根据随后收益挑选。当天没有可行配对时照实记录，不另造有利样本。

从选定的环境快照复制分支，比较立即离站与各候选 h 的**单次等待干预**。当前接拒、货物分配和路线保持一致，只调整等待及必要的依赖时序。分支保留完全相同的后续外生订单流；策略后续仍只收到当时可见信息，由相同冻结调度器继续决策，且不新增对未知需求的主动等待。先执行零干预续跑，并要求全日账本、接单量和轨迹哈希与原基线完全一致，验证快照恢复正确。

另有一条独立探索轨迹：在同一次停站最多安排三次主动复核，即首次干预加最多两次续等。它用于收集原离站策略看不到的连续驻站状态，**不是已经训练好或通过验证的等待策略**，也不代表无上限续等的效果。

标签保存全日净收益差 ΔΠ_h、已知计划回放净收益差 ΔJ_h，以及未来训练可用的残差：

\[
Y_h=\Delta\Pi_h-\Delta J_h.
\]

本轮仅收集与核验这些标签，不拟合权重、不在这32日上选择“最优固定间隔”，也不把单次反事实收益解释为整日自适应策略的收益。具体而言，每个运营日先运行无主动未来等待的冻结基线，在一个预定公开状态分别对固定间隔、空间与时间联合间隔、仅时间间隔干预一次，之后都由共同基线续接；至多三次续等的探索另列。**这不是让各策略独立控制整天所有等待决策的完整在线效果实验。** 32日是外生运营实例数，加上零干预校验和各反事实分支后，实际执行轨迹数更多，汇总单列已审计运行数。

## 3. 32日设计与信息边界

| 因素 | 预设水平 |
| --- | --- |
| 布局 | 610、611，共2个 |
| 每布局运营日 | day_id=0、1 |
| 全网订单总数 N | 100、150 |
| 动态度 d | 0.2、0.6 |
| 空间分布 | uniform、dual |

共2×2×2×2×2=32个运营日。布局种子与日期种子分离，同布局的不同日期有不同订单流。主设计固定取件数 round(Nd)，按既有1:3:2分时强度条件抽取释放时刻；这不是取件总数也随机的无条件泊松实验。

同一布局、日期、N、d的均匀／双簇实例共用释放时刻和重量，但各自按实际客户位置生成可行 I0。同一个实例内，各分支必须共用相同的订单、I0与公开预测。N、d及真实未来订单留在离线实例和环境中；在线策略只能读取历史预测和已披露信息，不能把实验分组参数当作当天已知总量。

先看等待候选是否实际出现、是否能被事件提前打断、延误是否只影响依赖作业、单次与连续复核是否产生不同结果，再分析净收益和账本差异。只有2个独立布局，本轮不提供确认性的置信区间或算法优越性结论。后续训练、选型和独立测试应使用新的、彼此隔离的布局。

## 4. 运行、输出与恢复

以下命令从仓库根目录进入研究代码目录执行：

```shell
cd code/e1_v04
python run_system_wait_pilot.py --workers 8
```

默认输出位于仓库的 `results/system_wait_pilot_20261125/`。可先在不同目录运行一个20单开发检查：

```shell
python run_system_wait_pilot.py --smoke --workers 1 --output ../../results/system_wait_smoke_20261125
```
